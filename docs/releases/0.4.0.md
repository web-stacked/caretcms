# CaretCMS 0.4.0

Version 0.4.0 changes how Caret handles Markdown paragraphs and interrupted
publishes. It also adds deployment reporting, per-editor permissions, and a
Cloudflare Durable Object adapter.

Markdown blocks on a page now have controls to split a paragraph at the cursor,
insert a block, merge adjacent blocks, delete a block, and undo the last change.
Paste is plain text, so unsupported markup does not enter the source. Block
changes stay in a draft until publication. Before writing, Caret checks that the
source range is still the one the editor started from.

When an edit changes one frontmatter field, Caret leaves the other frontmatter
and body text alone. The parser accepts YAML literal and folded multiline strings,
including indentation and chomping indicators. The supported syntax and known
limits are listed in the [frontmatter guide](../markdown-frontmatter.md).

If publication stops partway through a write, Caret records the steps that
finished. A retry starts with the first unfinished step. Bulk results identify
each completed entry, source conflict, and recovery case. See the
[recovery guide](../publish-recovery.md) for adapter requirements and migration
details.

Collections with more than 24 entries now work across multiple Studio pages.
Search covers IDs and displayed titles on every page.
Source read errors appear beside the affected entry, with a Retry action after
the source is repaired. Creation, deletion, history, and ordering dialogs now
keep keyboard focus inside the active control and restore it when they close.

After accepting a rebuild request, a deployment provider can return its build
ID and report whether the build is deploying, failed, or live. Caret shows Live
only when that report covers the commit or entry revisions just published. Core
includes a GitHub Deployments provider and a simulated provider for local tests.
Rebuild hooks have a timeout. Supported adapters keep enough information for an
editor to retry deployment after draft cleanup.

The Cloudflare package exports a SQLite-backed Durable Object adapter. One
transaction covers an entry and its revision, history, collection index, and
related reorder changes. KV remains available for deployments with one writer.

Sites with an authoritative identity provider can attach permission rules to
editing, publishing, deletion, collection management, and uploads. When rules
are enabled, drafts are isolated by editor. A bulk publish checks every entry's
permissions before writing any of them.

Existing structured drafts created before 0.4.0 do not contain the base snapshot
used for conflict detection and must be reapplied before publication. Astro 6
and Astro 7 are supported. The minimum Node.js version is 22.12.

The [changelog](https://github.com/web-stacked/caretcms/blob/v0.4.0/CHANGELOG.md)
has the complete list of changes.
