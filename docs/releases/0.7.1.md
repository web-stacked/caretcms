# CaretCMS 0.7.1

0.7.1 is the first npm release of the 0.7 line: 0.7.0 was tagged but not
published. It contains everything in [0.7.0](0.7.0.md) (Changes on the page,
"since you were last here", choosing what to publish, undoing a publish, page
history), plus one new feature and the fixes below. They were found by using
0.7.0 with two editors signed in at once, on a large open-source Astro
template that keeps its content in a folder per language, and on a new
template set up from scratch.

## Upgrading

Install `@caretcms/core@0.7.1`. If you use `@caretcms/cloudflare`, install
0.6.1 with it. `@caretcms/caretize` is 0.6.2. There is nothing to migrate.

If your site has Markdown entries in sub-folders, delete the `.astro` folder
once after upgrading. Astro caches rendered Markdown, and their body text is
only editable once it has been rendered again.

## Entries in sub-folders are editable

A collection that keeps its Markdown in sub-folders, such as
`src/content/blog/en/post-1.md` with one folder per language, used to show as
"0 entries" in the Studio, and nothing from it could be edited on the page.

Entry ids can now be paths, as Astro names them: that file is `en/post-1`, and
`guides/index.md` is `guides`. These entries are listed in the Studio, open at
`/admin/cms/blog/en/post-1`, are edited on the page (frontmatter and body
text), and publish to their own file. A new entry can be given a path id; its
folders are created.

Every segment of an id follows the old rule (lowercase letters, digits, `-`
and `_`, starting with a letter or digit), so an id can't leave its collection
folder.

If you wrote your own storage adapter: its methods can now receive ids that
contain `/`. `ENTRY_ID_RE` in `@caretcms/core/contracts` is the grammar.

## Two people editing the same section

A draft was compared with the site one top-level field at a time. When one
person changed `hero.headline` and another `hero.subtext`, that was reported
as one conflict on the whole `hero` object, shown as JSON, and **Use the
site's version** dropped the unrelated value too. This was in 0.6.3 and 0.7.0.

Drafts are now compared value by value inside objects. Different values merge,
and a conflict names the one value ("Hero › Headline") with both texts. A list
that both sides changed is still one conflict, because its items can't be
matched safely.

## Page history covers body text

In 0.7.0, page history ignored Markdown body text: a publish that only changed
a paragraph wasn't a version at all, and **Restore this version** brought back
titles and other fields but left the paragraph as it was.

Now each such publish is a notch on the slider. Stepping back shows each
paragraph as it was (outlined), hides paragraphs added since and shows removed
ones again. **Restore this version** brings the body text back with that
version's whole source file, as History in the Studio does. A whole version of
body text can't be a draft, so this publishes at once; on a site with drafts,
the panel says so before you click.

The slider also got a notch per version (click one to jump there), "Oldest"
and "Now" at its ends, and the date each version was published.

On a site with drafts, page history in 0.7.0 showed the editor's own draft
saves rather than the site's publishes. It now shows the site's history.

## Studio forms

Found by setting CaretCMS up on a new template the way a new user would:

- **A new entry couldn't be created in a collection with a choice field.**
  The form showed the first option as chosen but treated it as empty, so
  **Create** did nothing.
- **A date written as a day showed as empty.** `pubDate: 2026-05-20` under
  `z.coerce.date()`, as most Astro blogs have it, opened in a date-and-time
  picker. It now opens as a date and stays a day.
- **An Astro `reference()` field showed as JSON** (`"mara"`, with quotes), and
  an id typed without quotes was ignored without a word. It is a plain text
  field now. Other JSON fields say when the text isn't valid JSON.
- **The Studio saved defaults nobody chose.** Changing a post's date also
  wrote `draft: false` into its file. A default the entry doesn't store is
  saved only once you change it.
- **New entry** offers the collection's folders when its entries are in
  folders, and starts in the most used one.
- Changing one item of a list of objects in frontmatter no longer rewrites
  every item: `- day: Tuesday` stays as it is.
- Editing one item of a list that only the template held no longer lists the
  items before it as changes.
- An entry about to be deleted is named by its title in the Publish dialog.

## Other fixes

- A `data-caret` on the same element as its `data-caret-scope` looked editable
  but never saved. An element's own scope now counts. Text whose binding can't
  be resolved is no longer editable, and says why.
- **Changes** marks edited Markdown body text; it used to say nothing on the
  page had changed.
- Lists and groups in the Changes card, the conflict dialog and the Publish
  dialog read as their texts, not as JSON.
- **Page history** shows rich text and the template's own text for the time
  before anything was saved, and no longer lists versions that look the same
  as the page does now.
- On a site that saves live, **Restore this version** says the version is back
  on the site, and the restore isn't announced back to you as someone else's
  change.
- **Undo** is not offered for a publish that changed body text (History
  restores those), and **Undo last publish** goes away once the page has
  changed since.
- "Since you were last here" gives a time for changes made earlier today, and
  shows a single change without a step counter.

## API

- `conflicts[].fields` and `GET /api/cms/draft?changes=1` name nested values
  by path (`hero.headline`).
- Publish results carry `text: true` for an entry whose body text changed.
- `GET /api/cms/history` returns `template`, the template's text per binding,
  `body`, today's Markdown body text, and `body` on each version that has one.
  `published=1` returns the site's history instead of the editor's own saves;
  `POST /api/cms/history` takes `published: true` to restore from it.
- Entry ids in every route may contain `/`.

## Requirements

Node.js 22.12 or newer, and Astro 6 or 7. Tested on Astro 6.0.0 and 7.2.4, on
Cloudflare (KV, R2 and Durable Objects), and by hand on two static and
server-rendered Markdown sites.

The [changelog](https://github.com/web-stacked/caretcms/blob/v0.7.1/CHANGELOG.md)
lists every change.
