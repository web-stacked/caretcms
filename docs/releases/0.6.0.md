# CaretCMS 0.6.0

This release redesigns the Studio and the on-page toolbar, makes everyday
editing simpler and safer, and fixes 22 bugs found in a review of the 0.5.0
code. Edits now save on their own with Undo, drafts say what Publish will do,
and a newly tagged site's Studio lists its pages before anything is saved. Most
of the bugs are races between concurrent edits, or cases where invalid data
could be saved. Six are security fixes.

Some changes affect stored data, API responses, permission policies and Studio
dictionaries. Read the upgrade steps below before you deploy, especially on
Cloudflare.

## Upgrading

On Cloudflare, deploy the new Durable Object class at the same time as
`@caretcms/cloudflare` 0.6.0. The new adapter sends commands the old class does
not support, and the old class refuses them.

If several sites share one KV namespace with different `keyPrefix` values,
earlier releases wrote every site's private drafts to the same unprefixed keys.
0.6.0 writes them under each site's prefix. Back up the old `draft/` and
`session/` keys and move each draft to the site it belongs to. CaretCMS cannot
tell which site owns an old key, so it does not move them for you.
[Cloudflare upgrades](../cloudflare-upgrades.md) has the details.

Clients that call the mutation API directly should copy `baseRevision` from
merged draft views into `expectedBaseRevision`. If the base entry has changed
since the client read it, the server returns 409 with `currentBaseRevision`.
The bundled editor and Studio already do this.

Git-on-publish now needs the adapter to implement `preparePublicationSources`.
The built-in file adapters do. A custom adapter without it still publishes, but
no Git commit is made.

YAML frontmatter with an unknown escape sequence such as `"\q"` now fails to
load. Earlier releases changed the text silently. Fix the escape in the file.

Earlier releases did not record that a collection had been deleted, so bundled
seed entries could come back. If you deleted a collection before upgrading,
delete it again.

If your identity adapter has an `authorize` policy, creating an entry in the
Studio now needs the new `create` action as well as `edit`. A policy that
returns `true` only for actions it knows denies creation until it also allows
`create`. A first save to content a page already shows is still an `edit`.
[Permissions](../authorization-policy.md) lists every action.

Draft mode is now decided by the server: static delivery, or an active
authorization policy, makes every edit a private draft. Server delivery without
a policy saves field edits live. The `caret_preview` cookie is no longer read.

Studio dictionaries: `entry.saveNow` ("Save now") replaces `entry.saveLive` and
`entry.saveDraft`. The Save button appears only while changes are waiting.

`@caretcms/zod` no longer repeats a `.describe()` that became a field's label as
help text. Pair `.meta({ title })` with `.describe()` to show both.

Stored page layouts keep any well-formed section key. The built-in list of
section keys, and its renames of old keys, are gone; name sections in your
templates with `data-caret-section-label`.

In dev, the temporary password is kept in `.caret/dev-password` (also shown by
`astro dev logs`). Astro 7 runs `astro dev` in the background, so it no longer
reaches the terminal.

## A redesigned Studio

The Studio has a sidebar listing every collection, and a **Go to** search
(⌘K, or Ctrl K) that finds collections and entries across the site. It follows
your system's light or dark setting, and the switch at the bottom of the
sidebar lets you pick one. Collections have a page header, a grid or list view,
and status labels for published and hidden entries. Entry forms sit on cards,
one per field group.

The Studio now opens over the site instead of on a page of its own. The
toolbar's Studio button opens it as a drawer that moves the page aside, so all
of the page stays in view. (A site whose fixed elements don't move with the
page can add `caret-studio-overlay` to `<html>` or `<body>` to keep the drawer
over it instead.) **Expand** widens
it to two thirds of the window, with the page still beside it, and **Shrink**,
**Close**, Esc or **View site** put you back where you were. A Studio address
opened in a tab, such as a bookmark of `/admin/cms/pages/about`, shows the page
that entry appears on with the Studio expanded over it. Sites with
`enableInlineEditor: false` keep the Studio as a page.

On the site, the toolbar is now a small floating bar instead of a strip across
the bottom of the page. It moves aside when the Studio drawer is open, and on a
phone it fits the screen with an icon-only Sign out. A status pill on the
toolbar says Live or Draft, shows saving and unsaved states, and opens a panel
with the details and History.

A theme's `tokens` apply to both light and dark modes. If you set surface or
text colors for the old dark-only Studio, check them in light mode.

## Simpler, safer editing

- Text on the page, Markdown body blocks and Studio forms save on their own.
  Each save offers Undo, Cmd/Ctrl+Z undoes the last one, and History shows what
  each change did, marking the words that changed.
- When someone else saved the same entry, the Studio shows both versions side
  by side. Nothing of theirs is overwritten until you choose Keep my edits or
  Load latest.
- Static sites and policy-driven sites draft every edit. The Studio lists
  unpublished changes with Publish and Discard, and the dialogs name how many
  changes they affect.
- Required fields can't be saved empty, upload refusals say why, dates use a
  date picker, and fields an editor may not change are shown read-only.
- The Studio drawer opens the entry for the page you're on, search finds text
  inside entries, and ⌘K runs actions such as creating an entry.
- Keyboard and phone: a skip link reaches the toolbar, arrow keys move through
  it, and Studio fields don't zoom on phones.

## A first run that shows your content

`npx @caretcms/caretize init` installs and wires CaretCMS, then tags your
content, in one command. Afterwards the Studio lists every page caretize
tagged, with the text the page shows, before anyone has saved anything. Saving
from the Studio stores only what you changed, so text nobody edited keeps
following the template. Collections that exist only in templates don't offer
New, Arrange or Delete.

In production, the sign-in page lists any missing settings (`CARET_EDIT_PASSWORD`,
`CARET_SESSION_SECRET`) instead of failing after you submit.

## Themes that load content from data

Many Astro themes keep their copy in content collections and JSON files and
pass it to components as props, so there is nothing in the markup to tag. We
tried 0.6.0 on three marketplace themes built this way:
[Marby](https://github.com/agnilem/marby-astro),
[Elias Vent](https://github.com/agnilem/elias-vent-astro), and
[Larkin](https://github.com/alderthemes/larkin). Caretize could tag a few
labels on each. Now, with no changes to the themes, about 80% of the home page
text on Marby and Elias Vent is editable, and so is every item on Larkin's menu.

- Values read with `getCollection()` or `getEntry()`, and JSON files imported
  from `src/content`, are editable on the page. Editors see their drafts after
  a reload. Strings that code compares, such as a category from a `z.enum`, an
  icon name, or a link, are left alone, so filters and navigation keep working.
- Publish writes the change back to the Markdown file or into the JSON file,
  changing only the edited values. A hand-formatted file stays as it was.
- Studio forms use the schemas Astro generates from `content.config.ts`, with
  dropdowns for enums, toggles for booleans, and the right required fields.
- Images and links from data work in edit mode, and the images can be replaced.
  Replacing an image no longer adds a wrapper element, so background and
  carousel images keep their layout.
- Caretize no longer gives data-driven images invented keys, and skips
  elements that a script animates.
- `astro dev` reads `CARET_SESSION_SECRET` and `CARET_EDIT_PASSWORD` from
  `.env`, and `caretize init` adds CaretCMS's local files to `.gitignore`.

Copy kept in translation dictionaries, such as Larkin's `src/i18n/en.json`
read through a `t()` helper, is not editable on the page yet.

## Security

The rewrite engine used to find `data-caret` attributes anywhere in the HTML,
including inside comments, attribute values, and `<script>` text. It now reads
only real element tags, so text that looks like a binding can no longer be
replaced with stored content.

Sanitization decoded HTML entities more than once in some paths. It now decodes
one layer, and URLs are checked after decoding.

Editor, Studio, and API responses now send `Cache-Control: private, no-store`.
A shared cache could previously store a signed-in editor's draft page.

Login and upload requests are now limited in size while the body is read.
Before, the full body was buffered first.

On Cloudflare, Worker session cookies are now verified before a private
overlay is chosen, and prefixed KV sites no longer share draft keys.

## Concurrency and data integrity

Reads, writes, collection changes, history restore, and Git journaling now use
the same locks. A reader can no longer see content from one revision paired
with the revision number of another. Deleting and recreating a collection
cannot bring back an old revision number or a removed seed entry.

Publishing, layout changes, and history restore now validate the entry against
its schema first. A failing publish returns `invalid_entry` and keeps the
draft. `anyOf` and `oneOf` schemas are validated correctly, including nested
references.

Git-on-publish now commits the exact bytes the editor approved, using its own
index, and does not touch your working tree or staged changes. Set
`CARET_GIT_JOURNAL_RETRY=true` to have an interrupted Git commit finish on the
next attempt without publishing again. The Astro dev toolbar then shows
**Retry Git history** while any Git commit is still pending; editors aren't
asked to fix it. See
[publish recovery](../publish-recovery.md#durable-git-history-retry-opt-in).

Caretize writes each file atomically. It refuses to write a file that changed
after it was scanned.

## For adapter authors

`StorageAdapter` has new optional methods for consistent reads, batched reads,
publication sources, recovery overlays, and telling document collections
from data files (`isDocumentCollection`). Run the conformance suite from
`@caretcms/core/testing/storage` against your adapter.
[Storage adapters](../storage-adapters.md) explains each method.

## Requirements

Node.js 22.12 or newer, with Astro 6 or 7. CI now installs the packed packages
into a separate project and runs it on Astro 6.0.0 and 7.2.4, on Node 22.12 and
24. It also reopens Cloudflare data written by 0.5.0.

The [changelog](https://github.com/web-stacked/caretcms/blob/v0.6.0/CHANGELOG.md)
lists every change. The
[hardening record](../product/release-hardening-2026-09.md) explains each fix.
