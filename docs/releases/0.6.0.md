# CaretCMS 0.6.0

This release fixes 22 bugs found in a review of the 0.5.0 code. Most are races
between concurrent edits, or cases where invalid data could be saved. Six are
security fixes. The editor interface is the same, except for a new **Retry Git
history** button that appears when the opt-in Git retry has unfinished work.

Some fixes change stored data or API responses. Read the upgrade steps below
before you deploy, especially on Cloudflare.

## Upgrading

On Cloudflare, deploy the new Durable Object class at the same time as
`@caretcms/cloudflare` 0.6.0. The new adapter sends commands the old class does
not support, and the old class refuses them.

If several sites share one KV namespace with different `keyPrefix` values,
earlier releases wrote every site's private drafts to the same unprefixed keys.
0.6.0 writes them under each site's prefix. Back up the old `draft/` and
`session/` keys and move each draft to the site it belongs to. CaretCMS cannot
tell which site owns an old key, so it does not move them for you.
[Cloudflare upgrades](../cloudflare-upgrades.md) has the details.

Clients that call the mutation API directly should copy `baseRevision` from
merged draft views into `expectedBaseRevision`. If the base entry has changed
since the client read it, the server returns 409 with `currentBaseRevision`.
The bundled editor and Studio already do this.

Git-on-publish now needs the adapter to implement `preparePublicationSources`.
The built-in file adapters do. A custom adapter without it still publishes, but
no Git commit is made.

YAML frontmatter with an unknown escape sequence such as `"\q"` now fails to
load. Earlier releases changed the text silently. Fix the escape in the file.

Earlier releases did not record that a collection had been deleted, so bundled
seed entries could come back. If you deleted a collection before upgrading,
delete it again.

## Security

The rewrite engine used to find `data-caret` attributes anywhere in the HTML,
including inside comments, attribute values, and `<script>` text. It now reads
only real element tags, so text that looks like a binding can no longer be
replaced with stored content.

Sanitization decoded HTML entities more than once in some paths. It now decodes
one layer, and URLs are checked after decoding.

Editor, Studio, and API responses now send `Cache-Control: private, no-store`.
A shared cache could previously store a signed-in editor's draft page.

Login and upload requests are now limited in size while the body is read.
Before, the full body was buffered first.

On Cloudflare, Worker session cookies are now verified before a private
overlay is chosen, and prefixed KV sites no longer share draft keys.

## Concurrency and data integrity

Reads, writes, collection changes, history restore, and Git journaling now use
the same locks. A reader can no longer see content from one revision paired
with the revision number of another. Deleting and recreating a collection
cannot bring back an old revision number or a removed seed entry.

Publishing, layout changes, and history restore now validate the entry against
its schema first. A failing publish returns `invalid_entry` and keeps the
draft. `anyOf` and `oneOf` schemas are validated correctly, including nested
references.

Git-on-publish now commits the exact bytes the editor approved, using its own
index, and does not touch your working tree or staged changes. Set
`CARET_GIT_JOURNAL_RETRY=true` to have an interrupted Git commit finish on the
next attempt without publishing again. The toolbar then shows **Retry Git
history** while any Git commit is still pending. See
[publish recovery](../publish-recovery.md#durable-git-history-retry-opt-in).

Caretize writes each file atomically. It refuses to write a file that changed
after it was scanned.

## For adapter authors

`StorageAdapter` has new optional methods for consistent reads, batched reads,
publication sources, and recovery overlays. Run the conformance suite from
`@caretcms/core/testing/storage` against your adapter.
[Storage adapters](../storage-adapters.md) explains each method.

## Requirements

Node.js 22.12 or newer, with Astro 6 or 7. CI now installs the packed packages
into a separate project and runs it on Astro 6.0.0 and 7.2.4, on Node 22.12 and
24. It also reopens Cloudflare data written by 0.5.0.

The [changelog](https://github.com/web-stacked/caretcms/blob/v0.6.0/CHANGELOG.md)
lists every change. The
[hardening record](../product/release-hardening-2026-09.md) explains each fix.
