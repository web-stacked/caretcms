# CaretCMS 0.6.0

This release changes how editing feels. Edits save on their own, and each save
can be undone. The Studio has a new design and opens over your site. Drafts say
what Publish will do. A newly tagged site's Studio lists its pages before
anyone saves anything.

It also fixes 22 bugs from 0.5.0. Most were races between editors saving at
the same time, or ways to save invalid data. Six were security bugs.

Text your pages read from content collections and data files can now be edited
on the page, and CaretCMS works with more of Astro: view transitions,
server-rendered sites, `file()` collections, `getStaticPaths` pages and
`reference()` fields.

Some changes affect stored data, API responses, permission policies, Studio
dictionaries and Studio URLs. Read the upgrade steps first, especially if you
deploy on Cloudflare.

## Upgrading

### Cloudflare

Deploy the new Durable Object class at the same time as `@caretcms/cloudflare`
0.6.0. The new adapter sends commands the old class refuses.

If several sites share one KV namespace with different `keyPrefix` values,
earlier releases saved every site's private drafts under the same keys. 0.6.0
saves them under each site's prefix. Back up the old `draft/` and `session/`
keys, then move each draft to its site by hand. CaretCMS can't tell which site
an old key belongs to. [Cloudflare upgrades](../cloudflare-upgrades.md) has the
details.

### API and adapters

If you call the mutation API directly, copy `baseRevision` from the entry the
API returned into `expectedBaseRevision`. When the published entry has changed
since you read it, the server answers 409 with `currentBaseRevision`. The bundled editor
and Studio already do this.

Git-on-publish now needs the adapter to implement `preparePublicationSources`.
The built-in file adapters do. A custom adapter without it still publishes, but
makes no Git commit.

### Content

YAML frontmatter with an unknown escape, such as `"\q"`, now fails to load.
Earlier releases changed the text without saying so. Fix the escape in the
file.

Earlier releases didn't record that a collection was deleted, so bundled seed
entries could come back. If you deleted a collection before upgrading, delete
it again.

### Permissions

If your identity adapter has an `authorize` policy, creating an entry in the
Studio now needs the new `create` action as well as `edit`. A policy that only
returns `true` for actions it knows will deny creating until it allows
`create`. The first save to content a page already shows is still an `edit`.
[Permissions](../authorization-policy.md) lists every action.

### Drafts

The server now decides when edits are drafts. With static delivery, or with an
authorization policy, every edit is a private draft. With server delivery and
no policy, field edits go live when saved. CaretCMS no longer reads the
`caret_preview` cookie.

### Studio and editor text

In Studio dictionaries, `entry.saveNow` ("Save now") replaces `entry.saveLive`
and `entry.saveDraft`. The Save button only appears while changes are waiting.

The on-page editor now uses the same dictionary. Its messages are `editor.*`
keys, with Spanish translations. Setting `locale: "es"` translates the toolbar,
notices and dialogs on the page as well as the Studio, and `dictionary` can
override any of them.

### Studio URLs and the drawer

A Studio address opened in its own tab, such as a bookmark of
`/admin/cms/pages/about`, now shows the page that entry appears on, with the
Studio open over it. Bookmarks keep working. Sites with
`enableInlineEditor: false` keep the Studio as a separate page.

The Studio drawer now moves the page aside when it opens. The opt-in
`caret-push-content` class is gone. If your layout doesn't work with the page
pushed aside, add `caret-studio-overlay` to `<html>` or `<body>`, and the
drawer covers the page.

### Static and server-rendered sites

Static builds no longer include `data-caret` attributes in the HTML visitors
get. CaretCMS doesn't use them there. If your own scripts read them, use your
own attributes.

On a server-rendered site, each request now reads the stored values for content
collections, `getStaticPaths` props and imported data files. Visitors see edits
published after the build. Pages marked `prerender = true` still only change
when you build again.

### Other changes

`@caretcms/zod` no longer repeats a `.describe()` text as help when it's
already the field's label. Use `.meta({ title })` with `.describe()` to show
both.

Stored page layouts keep any well-formed section key. The built-in list of
section keys, and its renames of old keys, are gone. Name sections in your
templates with `data-caret-section-label`.

In dev, the temporary password is in `.caret/dev-password`, and
`astro dev logs` shows it. Astro 7 runs `astro dev` in the background, so the
password no longer appears in the terminal.

## The Studio

The Studio has a sidebar with every collection. Go to (⌘K, or Ctrl K) searches
collections and entries across the site. The Studio follows your system's light
or dark setting, and a switch in the sidebar lets you pick one. Collection
pages have a header, a grid or list view, and labels for published and hidden
entries. Entry forms are grouped on cards.

The Studio opens over your site. The toolbar's Studio button opens it as a
drawer beside the page, and the page moves aside so all of it stays visible.
Fixed headers and cookie bars move with it. Expand widens the drawer to two
thirds of the window, with the page still next to it. Shrink, Close, Esc and
View site all take you back to where you were. In the expanded Studio, Esc
shrinks it first.

The toolbar is now a small bar that floats over the page. It moves aside when
the drawer is open. On a phone it fits the screen, and Sign out is an icon. A
status pill on the toolbar says Live or Draft, shows when a change is saving or
not saved yet, and opens a panel with details and History.

A theme's `tokens` now apply in light and dark mode. If you set surface or text
colors for the old dark-only Studio, check them in light mode.

## Editing

Text on the page, Markdown body paragraphs and Studio forms save on their own.
Each save shows an Undo button, and Cmd/Ctrl+Z undoes the last save. History
shows what each change did and marks the words that changed.

When someone else has saved the same entry, the Studio shows both versions side
by side. Their changes stay until you choose Keep my edits or Load latest.

On static sites and sites with an authorization policy, every edit is a draft.
The Studio lists the changes that aren't published yet, with Publish and
Discard. Both dialogs say how many changes they affect.

Required fields can't be saved empty. When an upload is refused, the editor
says why. Date fields use a date picker. Fields an editor isn't allowed to
change are shown read-only.

The Studio drawer opens on the entry for the page you're on. Search finds text
inside entries. ⌘K also runs actions, such as creating an entry.

A skip link reaches the toolbar, and the arrow keys move through it. Studio
fields don't zoom in on phones.

## First run

`npx @caretcms/caretize init` installs CaretCMS, adds it to your config, and
tags your content, in one command. The Studio then lists every page caretize
tagged, with the text each page shows, before anyone saves anything. Saving
from the Studio stores only what you changed, so text nobody edited still comes
from the template. Collections that only exist in templates don't offer New,
Arrange or Delete.

In production, the sign-in page lists any missing settings
(`CARET_EDIT_PASSWORD`, `CARET_SESSION_SECRET`). Before, sign-in failed after
you submitted the form.

## Content from collections and data files

Many Astro sites keep their text in content collections and JSON files, and
pass it to components as props. There's no text in the markup for caretize to
tag, so before 0.6.0 most of it couldn't be edited. Now it can, with no changes
to your templates.

- Values a page reads with `getCollection()` or `getEntry()`, and JSON files
  it imports, are editable on the page. Editors see their drafts after a
  reload.
- Values the page's code compares are left alone, so filters and links keep
  working. Examples are a category from a `z.enum`, an icon name, and a URL.
- Publish writes changes back into the Markdown or JSON file and only touches
  the edited values. A hand-formatted file keeps its formatting.
- Studio forms use the schemas Astro generates from `content.config.ts`. Enums
  become dropdowns, booleans become toggles, and required fields match.
- Images and links that come from data work in edit mode, and those images can
  be replaced. Replacing an image no longer wraps it in a new element, so
  background and carousel images keep their layout.
- caretize no longer invents keys for images that come from data, and it skips
  elements a script changes.
- `astro dev` reads `CARET_SESSION_SECRET` and `CARET_EDIT_PASSWORD` from
  `.env`. `caretize init` adds CaretCMS's local files to `.gitignore`.

Text kept in translation dictionaries, such as a `src/i18n/en.json` read
through a `t()` helper, can't be edited on the page yet.

## Works with more of Astro

- Sites that use view transitions (`<ClientRouter />`) keep the editor working
  after moving to another page. The Studio drawer no longer adds entries to the
  browser history, so the Back button stays on the site's pages.
- On a server-rendered site, visitors see edits made after the build. Before,
  only signed-in editors did.
- Collections loaded with Astro's `file()` from any path, such as
  `src/data/menu.json`, can be edited on the page and in the Studio. Publish
  writes back into that file and keeps its formatting. `astro dev` lists any
  collections it can't edit, and why.
- On pages built with `getStaticPaths`, such as a blog post, the title,
  description and cover can be edited. Before, only the body could.
- `reference()` fields keep working while you edit, so an author's byline
  stays on the page.
- Values that caretize wraps in `editable()` are safe to edit. Editing the
  second item of a list no longer breaks the page. Fields the page's code
  compares stay as they are. Static builds include the published values. The
  Studio lists every item, with its default text.
- Saving or creating an entry in the Studio no longer writes values you didn't
  enter, such as an empty image path or the number -9007199254740991.
- If a saved change breaks a page, opening the Studio's address shows the
  Studio on its own page and explains what happened, so you can undo the
  change.

These can't be edited on the page yet: MDX post bodies, images shown with
astro:assets `<Image>`, and text in translation dictionaries.

## Security

The rewrite engine used to find `data-caret` attributes anywhere in the HTML,
including in comments, attribute values and `<script>` text. It now only reads
real element tags, so text that looks like a binding can't be replaced with
stored content.

Some code paths decoded HTML entities more than once. Sanitizing now decodes
once, and URLs are checked after decoding.

Editor, Studio and API responses now send `Cache-Control: private, no-store`.
Before, a shared cache could store a signed-in editor's draft page.

Login and upload requests now enforce their size limit while the body is read.
Before, the whole body was read first.

On Cloudflare, a forged session cookie now gets the public site, not an
editor's drafts. Sites with different KV prefixes no longer share drafts.

## Reliability

Reads, writes, collection changes, history restore and Git commits now use
the same locks. A read can no longer return content from one revision with the
number of another. Deleting and recreating a collection can't bring back an old
revision number or a removed seed entry.

Publish, layout changes and history restore now check the entry against its
schema first. If the check fails, publish returns `invalid_entry` and the draft
stays. `anyOf` and `oneOf` schemas are now checked correctly, including nested
references.

Git-on-publish now commits exactly the content the editor approved, using its
own Git index. It doesn't touch your working tree or staged changes. Set
`CARET_GIT_JOURNAL_RETRY=true` to let an interrupted Git commit finish on the
next try without publishing again. While a commit is still pending, the Astro
dev toolbar shows Retry Git history. Editors aren't asked to deal with it. See
[publish recovery](../publish-recovery.md#durable-git-history-retry-opt-in).

caretize writes each file in one step. It won't write a file that changed after
it scanned it.

## For adapter authors

`StorageAdapter` has new optional methods for consistent reads, batched reads,
publishing, recovering an interrupted publish, and telling Markdown collections
apart from data files (`isDocumentCollection`). Run the conformance suite from
`@caretcms/core/testing/storage` against your adapter.
[Storage adapters](../storage-adapters.md) explains each method.

## Requirements

Node.js 22.12 or newer, and Astro 6 or 7. Tested on Astro 6.0.0 and 7.2.4
with Node 22.12 and 24. Cloudflare data written by 0.5.0 opens in 0.6.0.

The [changelog](https://github.com/web-stacked/caretcms/blob/v0.6.0/CHANGELOG.md)
lists every change.
